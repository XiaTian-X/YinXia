# Cover Workflow

> 封面是含 Logo 的品牌物料（构图、文案、图像），生成逻辑与 Logo 资产不同。
> 封面放在项目仓库 `projects/<slug>/covers/NNN-名称/`，设计稿可以修改（靠 Git 历史追溯）。
> 平台与画幅登记见 `./logo cover platforms`（配置 `config/cover-platforms.toml`）。

## 1. 立项
1. 确认项目已有 Logo 发布（封面里的 Logo 只能来自发布）。
   **系列成员**：`./logo series` 显示系列已登记封面骨架时，先问用户“这张封面套用系列封面骨架吗？”，按回答加 `--from-skeleton` 或 `--no-skeleton`（不选会被拒绝），见“系列封面骨架”。
2. `./logo cover new <slug> <英文短名> --platforms youtube,x,xiaohongshu --title "中文标题" [--release rN]`
   - 按目标平台推出需要的画幅，每种画幅生成一份起稿 `<画幅>.svg`；
   - 生成 `cover.toml`（元数据，由命令维护，勿手改）与 `cover.md`（需求简报）。
3. **提交前填完 `cover.md`**：用途与背景、主信息（标题 / 副标题 / 行动号召）、视觉方向。提交后只能追加。
4. 起稿已按 Logo 图形的实际高度排好位置（共同安全区内、避开头像等遮挡区、手机显示不低于最小高度）；
   画幅太窄放不下时命令会提示，可在发布中提供更紧凑的 `icon.svg`。

调整目标平台：`./logo cover retarget <slug> <封面编号> --platforms <完整列表>`——新画幅自动起稿，
共用画幅的参考线按新平台组合重画（设计稿其余内容不动），并在 `cover.md` 末尾记录；正在上线的平台不能移除；
不再需要的画幅稿会保留并提醒，确认不用后删除。不要手改 `cover.toml`。

## 系列封面骨架（系列项目）
让同系列各品牌的封面一眼看出是一家：先在一张封面上定好版式骨架（Logo 位置、标题区、图片区），其他成员套用。
- **何时登记**：母品牌（或任一成员）的第一张封面定稿后，若 series.md“系列封面”约定统一骨架，问用户“以这张作为系列封面骨架吗？”；
  同意后 `./logo series skeleton <系列名> --from <项目> <封面编号> --note "<用户意见>"`（只能登记通过检查的成员封面；记录追加到 series.md）。
- **套用**：`./logo cover new <项目> <名称> --platforms … --from-skeleton`。骨架里有的画幅在骨架设计稿上改写：
  Logo 换成本项目发布的 Logo（位置、缩放、显示高度不变）；照片换成参考线里的“图片区”（素材授权按封面登记，须重新登记本封面的素材）；
  参考线按本封面平台重画；标题等内容保留作位置参考，骨架文字所用的字体自动写入 `[fonts] used`。骨架没有的画幅按常规起稿。
- **之后**：问用户本封面的标题文案与图片，写进 cover.md，再替换内容；内容仍是骨架原文时 `check` 会提醒。
  骨架之后被修改，套用过的封面会提醒“可对照调整”（只提醒）。

## 家族封面（系列项目）
同时展示多个品牌的封面（产品家族介绍、活动总览等），归属于系列，放在 `projects/_series/<系列名>/covers/`。
- **先问用户**（按 series.md“系列封面 / 家族封面”的约定）：“展示哪些品牌？以谁为主？”——第一个为主品牌，Logo 更大、底色取主品牌。
- 立项：`./logo cover new series:<系列名> <名称> --platforms … --members 主品牌,成员,…`（`--members` 必填、至少两个；成员须属于该系列且已发布）。
- 设计稿中每个成员一个 Logo 分组 `<g id="logo-<项目>">`，各自按该项目的发布核对，**只能移动、缩放**；起稿已把它们排成一行、避开遮挡区。
- 其余命令与项目封面相同，把项目名换成 `series:<系列名>`：`asset`、`preview`、`export`、`retarget`、`status`、`list`。
  越界、过小提醒逐个 Logo 给出（如“Logo（food）在 x 上会被遮挡”）；文字转曲所用字体只须在 fonts.toml 登记。
- 成员出新发布后会提醒；`./logo cover sync-logo series:<系列名> <封面>` 逐个成员换成当前发布（`--member <项目> [--release rN]` 只换一个）。
- 导出到 `projects/_series/<系列名>/dist/covers/`（不提交）。

## 导入外部生成的封面图（底图）
别处（其他 Agent、生图工具）生成的封面图作为**底图**导入，Logo 仍由系统从发布嵌入。先问用户：
- **图里有没有画 Logo？**（有就不能用——请对方重出不含 Logo 的底图：`./logo handoff brief <项目> --type cover --platforms …`）
- **图里有没有文字？**（可以用，但位图文字无法转曲，日后改文案须重做底图）
- 新封面用在哪些平台（`--platforms`）；或是给已有封面的某个画幅换底图（`--cover <编号> --ratio <画幅>`，每个画幅一张图）。
- 来源、使用条款（须用户确认）、候选还是成品。

1. `./logo cover import <项目|series:系列> <图片> --platforms … --contains-logo no --contains-text no|yes --analyze`
2. **把预演图发给用户**：比例与画幅一致的直接铺满；不一致的画幅同时给出“裁切铺满”与“完整放入（留边）”两种效果，
   问用户选哪种（`--fit 3x1=crop|pad`），或改项目——从 `--platforms` 去掉用这个画幅的平台。带上决定再预演一次。
3. 去掉 `--analyze`、补上用户确认的 `--source --terms --kind` 正式导入：新封面照常立项（系列骨架 / 家族成员照常询问），
   图片登记为素材（去掉元数据；SVG 渲染为 PNG）并放在底色之上；再导入同一画幅是替换。
4. 与用户填写素材说明的“用途与授权范围”（以及新封面的 cover.md），`cover preview` 给用户看后提交。

## 2. 收集素材
- 照片、插画：`./logo cover asset <slug> <封面编号> <图片> --name <短名> --source "<来源>" --license "<授权>"`，
  填完同名 `.md` 中的“用途与授权范围”。**未登记的图不能引用**；登记后不可替换，换图要重新登记。
- 设计稿中用 `<image href="assets/NNN-名称.png" …/>` 引用。
- 标题等文字：`./logo outline --font <id> --text "…" --fill "#HEX" --project <slug>` 转曲后粘贴。

## 3. 主视觉与多画幅延展
起稿 SVG 里有三个有含义的分组：
- `<g id="logo">`：从发布嵌入的 Logo。**只能移动、缩放**（改 `transform`），不能改内部；
- `<g id="content">`：标题、副标题、行动号召等**关键内容**，必须在共同安全区内；
- `<g id="guides">`：参考线（各平台裁切窗口、安全区、遮挡区、粗绿框的共同安全区），导出时去掉，可写文字标注。

做法：先在最重要的画幅定稿主视觉，再**改排**到其他画幅（不是简单缩放）。
设计规则：颜色不限于色板；可用已登记的位图；文字须转曲；禁止脚本、事件属性与外部资源；`viewBox` 固定为画幅画布。

## 4. 校对
- `./logo cover preview <slug> <封面编号> [平台…]`：每个画幅一行——画布（带参考线）、各平台裁切成品
  （叠红色遮挡区与绿框安全区）、手机缩略图（横幅 360px、竖版/方形 180px 宽）。
  总览图在 `.cache/<slug>/covers/<封面>/preview.png`，单张图在同一目录。**先自己看**：
  关键内容是否被裁掉或被头像/按钮遮挡，缩略图里标题与 Logo 是否还认得出。

校对提醒（`check`、`preview`、`export` 都会给出，只提醒不拦截）：
- **关键内容越界**：Logo 或 `content` 分组在某平台会被裁掉、超出安全区，或落进头像/按钮等遮挡区（按平台逐一判断，背景装饰不计）；
- **Logo 过小**：Logo 在手机显示宽度下低于最小高度（默认 16px，见 `config/cover-platforms.toml` 的 `[rules]`）；
- **Logo 过时**：封面用的不是项目当前发布；**上线中的封面优先提示**，已下线的不提示。
- **导出过期**（`preview`、`export`）：`dist` 中的图由旧版设计稿导出、来源不明或平台已不是目标，需要重新导出。

## 5. 检查与提交
- `./logo index && ./logo check`，然后 `git -C projects add -A && git -C projects commit -m "[<slug>] cover NNN: <说明>"`。
- 会被拦截：Logo 被改动、引用未登记或被替换的素材、文字未转曲、画布尺寸不对、缺少目标平台需要的画幅稿、简报未填完、
  文件名不是已登记的画幅。目录里的**每一份**设计稿都按同样规则检查（包括暂时用不到的预备画幅）。

## 6. 导出
- `./logo cover export <slug> <封面编号> [平台…]`：按平台尺寸导出 PNG 到 `projects/<slug>/dist/covers/<封面>/`（不提交），
  附 `manifest.json`，**逐张**记录平台、所用 Logo 发布、由哪份设计稿（及其 sha256）导出、系统与渲染器版本；
  只导出部分平台时，其余图保留各自原来的记录。同一设计稿再导出逐字节相同。
- 设计稿违反规则（Logo 被改、素材未登记等）时拒绝导出；简报未填完或仍是草稿可以导出（便于给人看初稿）。
- 导出结果含透明区域会提醒：封面通常应铺满底色。

## 7. 上线与更替
- Logo 出了新发布：`./logo cover sync-logo <slug> <封面编号> [--release rN]`，替换各画幅中的 Logo，
  保留位置、缩放、配色与显示高度（宽度随新比例变化），设计稿其余内容逐字保留（预备画幅一并更新）；之后 `cover preview` 确认再提交。
- `./logo cover status <slug> <封面编号> live --on x,youtube`（默认全部目标平台）；下线用 `archived`，草稿用 `draft`。
- `./logo cover list <slug>` 查看项目的封面、状态与上线平台。
